1. クイックスタート

作品を1つ足す最短の流れ。詳細は次章。

# 0) 作業ディレクトリへ（ずれると npm がエラーになるので毎回確認）
cd /Users/mirai/dev/portfolio

# 1) 作品フォルダを作る（NN=連番, slug=英小文字ハイフン）
mkdir -p content/projects/10-your-slug/images

# 2) index.mdx を作成（frontmatter + 本文）… ※3章の例をコピー
#    画像を content/projects/10-your-slug/images/ に置く

# 3) ローカルで確認（http://localhost:3000）
npm run dev

# 4) 本番ビルドが通るか確認
npm run build

# 5) 公開（main へ push → 数分で反映）
git add -A
git commit -m "作品10 追加: ◯◯"
git push origin main
ポイント dev/build の直前に sync-images が自動で走り、content/…/images の画像を圧縮して public/images にコピーします。画像はcontent側に置くだけでOK。

2. 新しい作品を追加する

  • フォルダ：content/projects/NN-slug/ を作り、中に index.mdx と images/ を置く。
    NN は連番（並び順は number の昇順。既存が 01〜09 なので次は 10）。slug は英小文字＋ハイフン。
  • index.mdx：先頭に --- で囲む frontmatter、その後に本文（Markdown/MDX）。3章の完全な例をコピーして書き換えるのが速い。
  • 画像：images/ に置く。1.jpg がカバー、Fig_◯◯.jpg が本文図（4章参照）。
  • プレビュー：npm run dev → /works/NN-slug/ を開いて確認。
  • ビルド確認 → push：npm run build が通ったら git push。sitemap・一覧・マーキー・詳細ページは自動で反映（手動登録不要）。

3. frontmatter リファレンス

必須 ／ 任意。型は src/lib/content.ts の ProjectMeta が正。

キー要否意味・使い方
number必須連番の文字列 "10"。一覧の並び順を決める（昇順）。
title必須作品名。詳細ページ見出し・一覧・OGP・タブに使用。
subtitle任意一覧カードとタイトル下に出る補足。
category必須research / entertainment / implementation のいずれか。
year必須"2026" など。
tagline必須一文キャッチ。検索の説明文(meta description)・OGPにも使われる。
keyPoints推奨詳細冒頭のスキャン用3点。{label,text} の配列。あれば長いabstract段落の代わりに表示。ラベルは 研究/ツール=「課題」、作品=「着想」→「アプローチ」→「成果」。
abstract任意詳細冒頭の要約（keyPoints が無いとき表示）。tagline の丸写しにしない（6章）。
team推奨制作体制・担当。個人は "個人制作"、チームは "グループ制作 / 干川は◯◯を担当"。複数行は | で。
teamType推奨"個人" / "チーム"。カード・詳細に出る制作体制タグ。
tags任意文脈タグ配列（例 修士課程研究 / 長期インターン）。
aiUsage推奨AI利用の明記（複数行）。選考等で重要。書式は6章。
tools任意使用ツールの配列。バッジ表示（src/data/skills.ts にロゴがあれば付く）。
achievements任意導入・展示実績の配列（文字列）。※「発表予定/投稿中」は原則載せない方針（6章）。
references任意書誌情報。"文字列" か {text, url}。url を付けると [link] になる。
cardImages任意一覧カードの画像上書き。1枚=単純差し替え／2枚=重ね表示（[前面/左下, 背面/右上]）。ファイル名で指定。
cardFit任意"contain" で横を切らず全体表示（単一カード＋詳細のabstract画像にも適用）。既定 cover。
marqueeImage任意トップの横スライド（マーキー）だけ差し替える画像ファイル名。
galleryLayout任意"grid" でギャラリーを小さめカラム表示。既定 full（全幅）。
cover任意カバー画像を明示指定（フルパス /images/projects/NN/xxx.png）。未指定なら 1.* が自動カバー。
heroImages任意ヒーロー用ファイル名配列（任意）。

完全な例（コピーして書き換え）

---
number: "10"
title: "作品タイトル"
subtitle: "一覧カードに出る短い説明"
category: "entertainment"        # research | entertainment | implementation
year: "2026"
tagline: "一文キャッチ（検索の説明文・OGPに使われる）"

keyPoints:                       # 詳細冒頭の要点3点（スキャン用）
  - label: "着想"                #  ← 研究/ツールなら "課題"
    text: "この作品が生まれた観察・問い。"
  - label: "アプローチ"
    text: "何をどう作ったか。技術・手法。"
  - label: "成果"
    text: "結果・展示実績・担当範囲（チームなら誰が何を）。"

team: "個人制作"                 # チーム例: "グループ制作 / 干川は◯◯を担当"
teamType: "個人"                 # 個人 | チーム
tags:
  - "修士課程研究"

aiUsage: |
  ◯◯の処理：自身で実装。
  映像：生成AIで作成し、自身で編集。

tools:
  - Python
  - TouchDesigner

achievements:
  - "◯◯展 出展（2026/7）"

references:
  - text: '著者, "タイトル," 学会, 2026年.'
    url: "https://example.org/paper"

# 画像まわり（任意・必要な時だけ）
cardImages:                      # 2枚=重ね / 1枚=差し替え
  - "1.jpg"                      #   [前面/左下, 背面/右上]
  - "Fig_setup.jpg"
cardFit: "cover"                 # contain=横を全部見せる
galleryLayout: "full"
---

4. 画像のルール

置き場所は必ず content/projects/NN/images/。ビルド時に scripts/sync-images.mjs が 最大幅1920pxに縮小＋圧縮して public/images/projects/NN/ へミラーします（jpg=mozjpeg, png=パレット圧縮, webp等はそのままコピー）。

命名役割
1.jpg / 1.png（数字始まり）一番小さい番号が自動カバー。残りの数字画像はギャラリーに並ぶ。
Fig_◯◯.jpg（数字で始まらない）ギャラリーには入らない。本文の <Fig> / <TextImage> で使う用。
重複に注意 カバー(1.jpg)を本文の <Fig> でもう一度出すと同じ画像が二重表示になる。本文で使う図は Fig_◯◯ のような数字始まりでない名前にする（＝ギャラリー重複も回避）。
豆知識 2枚重ねカードの前面はマスク処理する関係で、プログレッシブJPEGだと稀に表示されないことがある。前面用は WebP（例 Fig_front.webp）にすると確実。
大きすぎる元画像（10MB超）は事前に少し縮小してからコミットするとリポジトリが軽い（公開版はどのみち1920pxに圧縮される）。

5. 本文で使えるコンポーネント

MDX本文（## 見出しなどの間）で使えるタグ。src/figure はファイル名だけでOK（images/ から自動解決）。

タグ用途 / 例
<Fig>1枚の図＋キャプション（中央）。
<Fig src="Fig_x.jpg" caption="説明" />
<TextImage>図とテキストを左右に。
<TextImage figure="Fig_x.jpg" caption="説明" side="right">本文…</TextImage>
<FigGrid>図を横並び。中に <Fig> を複数。
<FigGrid cols={2}> …<Fig/>… </FigGrid>
<LinkCard>外部サイトのリッチリンク（記事埋め込み風）。著作権等で自前画像が出せない時にも。
<LinkCard src="Fig_x.jpg" href="https://…" title="…" description="…" />
<Video>YouTube/Vimeo 埋め込み。
<Video src="https://youtu.be/XXXX" />
<Callout>強調ボックス。
<Callout title="補足">…</Callout>
<NoImage>「画像なし」のプレースホルダ。
<NoImage caption="著作権の都合で非掲載" />

6. 書き方の統一ルール

これまで整えてきた方針。作品ごとにブレないことが読みやすさに直結する。

要点(keyPoints)のラベル

  • 研究・実務ツール（実問題を解くもの）＝「課題」
  • アート寄りの作品＝「着想」（作品が生まれた考え・観察）
  • 共通で 「課題/着想」→「アプローチ」→「成果」の3点。成果にはチームなら担当範囲も。

abstract / 本文

  • abstract は tagline の丸写しにしない。課題・着想から書き出す。
  • 段落は短く。長い一段落は分割 or 箇条書きに。
  • 生の数値表（平均±SD等）は載せない。要点は本文で1文にまとめる（例「操作を約6.4秒短縮、誤操作6→2」）。
  • 内部用の記号・略語（例 “a論理”）は残さない。読者に伝わる言葉に。

AI利用(aiUsage)

  • 工程ごとに「◯◯：自身で実装／△△：生成AIで作成」の形で明記。
  • 未使用なら定型で：本作では生成AIを使用していない。制作当時（YYYY年）は…、…自身で…した。

表記の統一

  • Fusion 360（間にスペース）／ SolidWorks ／ アート＆テクノロジー東北（全角＆）
  • 和文内の区切りは全角「／」、英字列挙は半角「/」。
  • 1作品の中で「珊瑚／サンゴ」等の表記を混ぜない。
  • Skills の見出しラベル「経験」は確定済み（“できること”に戻さない）。

実績・書誌

  • 「発表予定・投稿中」の論文/展示は原則載せない。載せるなら「（予定）」と明記。
  • 掲載済みの論文・展示にはURLを付ける（references の url、または profile.ts の publications/exhibitions）。

7. 公開前チェックリスト

  • number / title / subtitle / category / year / tagline を記入
  • keyPoints 3点（課題 or 着想 / アプローチ / 成果）
  • team ＋ teamType（＋必要なら tags）。チームは担当範囲を明記
  • aiUsage を明記
  • 画像を配置（カバー=1.*／本文図=Fig_*／必要なら cardImages）
  • 本文の図は数字始まりでない名前（カバー重複・ギャラリー重複を回避）
  • tools を記入
  • 表記統一（Fusion 360 / SolidWorks / 全角＆ 等）をチェック
  • 数値表を1文要約に、予定/投稿中の書誌を載せていないか確認
  • npm run build が成功する
  • git push → 数分後にライブで反映を確認

8. デプロイ & トラブル対処

main に push すると GitHub Actions「Deploy to GitHub Pages」が走り、数分で 公開サイトへ反映。

症状対処
npm がエラー（package.json が見つからない）作業ディレクトリのズレ。cd /Users/mirai/dev/portfolio してから実行。
画像が出ないcontent/…/images/ に置いたか確認 → npm run build（sync-imagesが public へコピー）→ ファイル名とfrontmatter/本文の綴り一致を確認。
変更が反映されないActions のデプロイ完了を待つ（数分）→ ブラウザをスーパーリロード（⌘⇧R）。
2枚重ねカードの前面が出ない前面画像を WebP にする（プログレッシブJPEG＋マスクの不具合回避）。
ページ遷移で見出しが消えるScrollReveal が pathname 依存で再監視する実装済み。もし再発したら「reveal が新ページで効いていない」と伝える。
よく使うコマンド npm run dev（ローカル確認）・npm run build（本番ビルド）・npm run sync-images（画像だけ手動ミラー）。

9. 定期 保守・点検

  • リンク点検：外部リンク（論文・展示・所属企業）が生きているか時々確認。切れたら url を更新/削除。
  • 実績の更新：展示・発表が「予定」→「実施済み」になったら文言とURLを更新。新しい登壇・受賞・採択は profile.ts（Records）へ。
  • 配信現場数：src/data/profile.ts の operations.summaryCount / summaryNote を随時更新。
  • プロフィール：所属・学年・bio は src/data/profile.ts。フッターの年表記等もここ・各コンポーネント。
  • ビルド健全性：たまに npm run build を通し、警告・エラーが無いか確認。
  • 依存更新：Next等のアップデートは npm install 後に必ず npm run build で確認してから push。
データはどこ？ 作品＝content/projects/ ／ 人物・経歴・実績・所属企業＝src/data/profile.ts ／ スキル・機材＝src/data/skills.ts ／ 見た目＝src/components/ ＋ src/app/globals.css。

10. 検索・SEO

  • 新しい作品は sitemap に自動追加（src/app/sitemap.ts）。各作品ページの title/description/OGP も自動生成。
  • 大きな追加をしたら、Google Search Console で該当URLを「URL検査 → インデックス登録をリクエスト」すると拾われが早い。
  • 検索順位は時間＋被リンクで上がる。GitHubプロフィール・SNS・研究室ページ等にサイトURLを貼るのが最も効く。
  • 所有権確認ファイル public/google6128a553499c9afa.html はそのまま残す（消すと確認が外れる）。
